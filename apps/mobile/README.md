# apps/mobile: the native app (Expo)

The phone app for Wandr (working name; the name comes from `packages/core/src/config.ts`). Started under
**D75**: sign-in, trips, ideas and voting, the library, the share sheet (FR-21) and push (FR-87).
It talks **only** to the versioned JSON API in `packages/api-contract` (`/api/v1`), through
`createApiClient` from `@wandr/api-contract/client`, which validates every response against the
contract's zod schemas.

Stack: Expo SDK 57 (React Native 0.86.3, the version SDK 57 pins), expo-router, TypeScript,
expo-secure-store, expo-notifications, expo-image, expo-haptics, expo-clipboard,
expo-share-intent 8 (SDK 57 line), Bricolage Grotesque for headings, system font for body.

## Run it

```sh
pnpm install                     # from the repo root
cd apps/mobile
cp .env.example .env.local       # EXPO_PUBLIC_API_MOCK=1 by default

# First time (and after adding native modules): build the dev client. Needs Xcode + CocoaPods.
npx expo run:ios                 # or: npx expo run:android
# After that, just start Metro:
pnpm start                       # or `pnpm start:mock` to force mock mode
```

Expo Go **won't work**: the share extension (expo-share-intent) is a native target, so this app
always runs as a development build (`expo run:ios` / EAS build). `ios/` and `android/` are
generated by `expo prebuild` and git-ignored (continuous native generation): change native
settings in `app.config.ts`, not in Xcode.

### Mock mode vs the real API

| | Mock (`EXPO_PUBLIC_API_MOCK=1`) | Real (`EXPO_PUBLIC_API_URL=…`) |
|---|---|---|
| Sign in | Any number, code **000000** (screen says "Test mode: use 000000") | Real texted code; the test hint shows only when the server says `testMode` |
| Trips | 3 seeded trips, one per size: group *Lisbon & Porto*, duo *Tokyo with Sam*, solo *Someday: Mexico City* | Your trips |
| Add idea / share | Card appears as "Finding the place…" and fills in after ~3.5 s with a fake place | Server extraction |
| Votes | Blind group tallies, Pass as count only, open duo votes: same rules as the server | Server |
| Invite | Returns a fake link; share sheet works | Server texts the personal link (D65) |
| Push | Registers a fake token on the simulator | Needs `EXPO_PUBLIC_EAS_PROJECT_ID` and a real device |
| State | In memory; resets when the JS reloads (your token survives, so you stay signed in) | Server |

The mock (`src/lib/mock/server.ts`) is a `fetch` replacement handed to the real contract client,
so mock responses are schema-checked exactly like server responses.

For a phone on Wi-Fi, set `EXPO_PUBLIC_API_URL` to your computer's LAN address
(`http://192.168.x.x:3000`); the simulator can use `http://localhost:3000`.

## Behaviour notes

- **2-tap voting (P4):** open the trip (tap 1, e.g. from a push), tap Must-do / Down / Pass (tap 2).
  Tapping your current vote again clears it (P7). Haptic tick on every vote.
- **Per trip size (§6.10):** solo shows Must-do / Maybe / Skip with no tallies; duo shows both votes
  ("You: Must-do · Sam: Down") and a one-line notice that votes are visible to each other (FR-T6);
  group shows "Vote to see how the group voted" until you vote, then the tally and Must-do/Down names
  (never Pass names, FR-42). The app only renders what the API returns; privacy is enforced server-side.
- **Clipboard:** iOS shows a paste prompt whenever an app reads the clipboard, so on iOS the Add screen
  only checks *whether* there is a URL (no prompt) and offers "Add the link you copied?"; the read
  happens on tap. Android reads it directly and names it ("Add the TikTok you copied?").
- **Share sheet:** iOS share extension and Android `text/*` intent filter accept URLs and text.
  The extension hands off to the app, which shows the sheet as a form sheet. Shares that arrive
  signed out go through sign-in first, then the sheet opens.
- **Push:** permission is requested only after the first trip is created; later launches re-register
  silently if already granted. Taps route via `{ tripId, ideaId? }`, `{ url }` or `{ screen: "library" }`.
- **Accessibility:** text scales with Dynamic Type; vote buttons are radios labelled "Must-do: <idea>"
  with hints; touch targets ≥ 44pt (vote buttons 56pt).

## Troubleshooting

- **Red screen on launch: "expo-linking needs access to the expo-constants manifest"**. The native
  build has no embedded Expo config. Cause: the repo path has spaces ("Group Travel App"), and two
  upstream iOS build scripts (expo-constants' "Generate app.config" phase and the React Native
  bundle phase) don't quote paths, so the config was never written. `plugins/with-path-spaces-fix.js`
  fixes both at prebuild time. **After pulling, rebuild the native app**: a JS reload alone won't
  pick it up.
  ```sh
  cd apps/mobile
  npx expo prebuild --platform ios --clean
  npx expo run:ios
  ```
  Check it worked: `find ~/Library/Developer/Xcode/DerivedData -path '*Wandr*.app/EXConstants.bundle/app.config'`
  should list a file. As a safety net the app passes its URL scheme to the share-intent library
  explicitly and, if expo-linking still can't build a URL, logs a warning and turns share intake
  off for that session instead of crashing.
- **"No such file or directory: …/Group" during `xcodebuild`**: same cause; re-run prebuild as above.
- **Expo Go shows errors about native modules**: use the dev build (`npx expo run:ios`), not Expo Go.

## Open questions (need a founder / API decision)

1. **Trip order in `GET /me`**: the share sheet defaults to "the most recently active trip" (FR-21).
   The app remembers the last trip opened on this phone and otherwise uses `trips[0]`. The contract
   should state that `trips` is sorted by recent activity.
2. **Screenshots / images in the share sheet (FR-20, FR-21)**: the contract has no upload endpoint,
   so the share extension accepts only links and text for now.
3. **Push payload shape**: the app accepts `{ tripId, ideaId? }`, `{ url }`, `{ screen: "library" }`.
   The server's push sender should agree on one.
4. **Who may invite**: the Invite button shows for every member; the server decides (403 shows its message).
5. **Email sign-in**: the contract supports `channel: "email"`, but D74 says phone; the app offers phone only.
6. **Universal links** (open `https://…/t/<id>` in the app) need the production domain and an
   `apple-app-site-association` file; not set up yet. `wandr://trip/<id>` works.
7. **Bundle id / EAS project id / app icon**: placeholders (`app.wandr.mobile`, none, default icon).
8. **Group card order**: FR-41 says shuffle until you vote; the app keeps the server's order, so the
   server should shuffle per viewer.
